=== SECURITY & MODERATION ===
- add 2FA support (free add-on?) (make required for cadmus_admin)
- add recaptcha / turnstile feature/option (free add-on?) -> Turnstile for *.cadmus.digital sites, reCAPTCHA for custom domains
- enable Cloudflare Leaked Credentials Detection in log mode; in auth handler, read the exposed-credential header and force a password reset on next login for flagged users
- add a local NSFW pre-filter (nsfwjs or similar) to scanner to reduce Vision API calls at scale — removed due to native addon issues in Cloud Run; revisit with a pure-JS model or sidecar approach
- add malware/virus scanning to the media scanner. Today the scanner only does CONTENT moderation (Cloud Vision SafeSearch on images/video-frames/PDF-thumbnails) + magic-byte MIME validation at upload — no AV. An authed editor can upload an arbitrary file (e.g. weaponized PDF) that's visually clean and we'd host/serve it to visitors. Add an AV pass in the scanner's staging step before approve (e.g. ClamAV sidecar/Cloud Run service, or a hosted scanning API); block/quarantine on hit. Mind the 100MB+ large-file path (we skip render there → would also need AV or route to manual review).
- custom-code injection hardening (feature shipped 5a97178 — owner-only raw head/body script injection via settings.customCode, rendered in BaseLayout). Follow-ups: (a) if/when we add a Content-Security-Policy header to served sites, owner-injected scripts will break unless nonce'd or the CSP is relaxed per-site for sites using customCode; (b) on shared *.cadmus.digital subdomains, keep any cookies set by injected scripts host-scoped — avoid anything on the parent .cadmus.digital domain that could leak across tenant subdomains (custom domains are already isolated); (c) consider a size cap + basic well-formedness check on the head/body code, and surfacing it in the audit log UI.

- remove dead signing code: after the upload (resumable) + read (stream proxy) migrations, getSignedUrl/getSignedUploadUrl in packages/cloud appear unused. Confirm no callers, then delete them + the signWithRetry helper, and consider dropping the api SA's tokenCreator-on-self grant (and the setup-infra line that adds it).
- Improve production deploy:
-- Startup/readiness probes for container-level health.
-- Tagged revision URL + smoke tests for canary verification.
-- Gradual traffic shifts for production promotion.
-- Cloud Monitoring / logs for error-rate validation during the ramp.
- Database connection scaling:
-- Add a connection pooler (Cloud SQL managed connection pooling, PgBouncer-based transaction mode) to decouple Cloud Run instance count from Postgres connection count. Root issue: each Cloud Run instance opens its own pool, so connections grow linearly with instances. Mitigated for now by lowering per-instance pool to max:4 (packages/db/src/client.ts) and bumping prod Cloud SQL f1-micro -> db-custom-1-3840 (max_connections=200). Revisit pooling when peak connections approach the ceiling (~sustained 150+).
-- Give dev its own Cloud SQL instance — dev + prod currently share the single `cadmus` instance (different DBs, same server/connection budget), so a dev spike or migration can starve prod.
-- Later scale knobs: vertical tier bumps for query throughput, read replicas for read-heavy traffic (sites/resolve, content reads), regional HA for SLA, in-memory/Redis cache for hot hostname->site lookups.
